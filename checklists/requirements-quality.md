# Requirements Quality Checklist

- [ ] Exactly one independently verifiable obligation per normative statement.
- [ ] BCP 14 keyword is intentional and uppercase.
- [ ] Priority is separate from normative force.
- [ ] No undefined weak qualitative term.
- [ ] Units, clocks, windows, limits, and counting scope are explicit.
- [ ] Nominal, malformed, boundary, timeout, cancellation, crash, and resource behavior covered where relevant.
- [ ] Acceptance evidence is observable.
- [ ] Failure behavior and category are explicit.
- [ ] Source or locked constraint recorded.
- [ ] Architecture, task, and test mappings resolve.
- [ ] No duplicate or contradiction.
- [ ] No TBD or hidden implementation decision.
